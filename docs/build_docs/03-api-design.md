# Seeker — REST API Design

Source of record: spec §6 (Core Engine REST API).

## Endpoints

```
POST   /v1/sources                 register a new connector
GET    /v1/sources                 list registered sources + sync status
POST   /v1/sources/{id}/sync       trigger a manual re-sync
DELETE /v1/sources/{id}            remove a source and its indexed content

POST   /v1/search                  semantic search
GET    /v1/status                  engine health, index size, last sync times
GET    /v1/health                  anonymous liveness probe (implemented addition,
                                   2026-10-26 — the only route without auth)
```

## POST /v1/search — request

```json
{
  "query": "budget disagreement doc from march",
  "top_k": 5,
  "filters": { "source_id": ["fs-home", "gdrive-personal"] }
}
```

## POST /v1/search — response

Shape as implemented 2026-10-26 (adds `chunk_id`, `page`, `position` to the spec's
example so a result can point back to its exact location):

```json
{
  "results": [
    {
      "chunk_id": "uuid",
      "document_id": "uuid",
      "title": "Q1 Marketing Spend.xlsx",
      "path": "/Users/you/Documents/finance/Q1 Marketing Spend.xlsx",
      "snippet": "...disagreement over the ad spend line item raised by finance...",
      "score": 0.83,
      "source_id": "fs-home",
      "page": null,
      "position": 0
    }
  ]
}
```

The sync response's `failed` field holds structured failure records since
2026-10-29 — `{"path", "error", "reason", "suggestion"}` per failed file, plus a
server-side traceback in the engine log; never a silent skip.

## Conventions

- JSON; ISO 8601 UTC timestamps.
- Errors return a machine-readable code in the body. Implemented codes
  (2026-10-26): `UNAUTHORIZED`, `VALIDATION_ERROR`, `SOURCE_NOT_FOUND`. The
  spec's `EMBEDDING_BACKEND_UNAVAILABLE` is not a route error — embedding
  failures surface per-file in the sync response's `failed` records instead.
  FastAPI's own 422 validation bodies keep FastAPI's default shape (noted in
  handover `01`, 2026-10-26).
- Every request carries an `X-Request-Id`; echoed in logs (and echoed back to
  the client in the `X-Request-Id` response header).
- Auth: bearer token (shared secret at personal scale; rotation story is open
  decision 8 in [`10-open-decisions.md`](10-open-decisions.md)).
- OpenAPI document generated by FastAPI is the contract of record.
